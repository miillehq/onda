# Security and privacy model

Onda handles microphone audio, transcripts, selected text, API keys and optional account credentials as sensitive data. The trusted components are the Rust application/domain services, the packaged shortcut/ASR workers, the operating system's audio, accessibility and clipboard APIs, and the AI provider the user explicitly enables. The WebView is a view/controller and must be treated as a less-trusted boundary. This document describes implemented controls, not a claim of third-party certification.

## Data flows and retention

Microphone data moves from the OS audio API (WASAPI, ALSA or Core Audio, through CPAL) through a bounded lock-free ring into 16 kHz memory and an isolated local ASR worker. No cloud speech endpoint is used. Raw recordings are not persisted. The current result stays in operation memory for copy/retry/undo. Dictation history (ADR 005) is kept for a user-set 0–30 days, default 3: each entry is encrypted for the signed-in user (a DPAPI blob with Onda-specific entropy on Windows; ChaCha20-Poly1305 under a random key that the desktop keyring or the macOS Keychain keeps, on Linux and macOS), stored in SQLite with `secure_delete`, and decrypted only in process memory. Retention 0 keeps history in memory only and deletes stored entries. SQLite also stores settings, dictionary/replacements, snippets, transforms and aggregate usage. Dictionary/snippet export is explicit and can contain user data; diagnostic export does not include their contents.

When AI polish is enabled, only the relevant transcript/source, retrieved vocabulary and enabled bounded focused-field context go to the chosen provider. ChatGPT's Responses requests use `store: false` and streaming with explicit limits/timeouts. This requests non-storage by the Responses service; it does not mean that OpenAI's applicable account/service processing policies cease to apply. Disabling enhancement keeps dictation local. Cloud refusal, timeout, quota failure, model removal, invalid output or offline state falls back to locally normalized dictation text. A selected-text transform preserves its original on failure. There is no automatic API-key/billable provider fallback.

Immediately before typing a dictation, Onda reads at most the two characters before the caret of the validated target to decide on a leading space; they are compared locally and never stored, logged or sent. Context requires user-enabled settings and a user-triggered operation; it reads only the focused field, through bounded accessibility reads (UIA TextPattern on Windows, AT-SPI on Linux, the Accessibility API on macOS). Password fields and unknown identities are refused. Optional learning samples that same focused field at most three times over twelve seconds and proposes conservative corrections; it does not record keystrokes or continuously scrape windows. Logs contain subsystem, operation ID, phase, selected backend/model and durations/error codes, and, when a target check fails, the target's executable name and which identity parts changed; never text/audio/tokens/OAuth URLs. The application rotates local logs with a seven-file bound. The explicit diagnostics response contains versions, hardware, selected preference flags, shortcut status and bounded performance metrics, without transcript/context/selected text, dictionary contents, email, account credentials or model paths.

On macOS the same reads go through the Accessibility API, and only after the user has turned Onda on under Privacy & Security › Accessibility. Onda asks for the focused application, its focused window and its focused element; the element's role, subrole, identifier, position and size identify it, and its selected text, value and the characters before the caret are read under the same rules as on Windows. Pasting posts ⌘V (key down and up, with the Command flag) through the HID event tap after the identity is checked again. A secure text field, or macOS's secure keyboard input being on for any app, refuses the paste. The pasteboard text is marked concealed while it holds the dictation and is put back afterwards if nothing else replaced it; other pasteboard contents (images, files) are not preserved. Onda cannot revoke the permission itself.

On Linux the same reads go through AT-SPI, and pressing paste in other apps goes through a remote desktop portal session that the user allowed once; its restore token is kept in the data folder, and stopping the session in the desktop turns typing off. The clipboard entry carries KDE's `x-kde-passwordManagerHint` so clipboard managers that honour it skip it ([linux.md](linux.md)).

Other AI providers (docs/ai-providers.md) follow the same rules: they receive text only when polish
or a rewrite is used, only from the provider the user chose, never with a fallback to another one.
Their API keys live in DPAPI files (Windows), the Secret Service (Linux) or the Keychain (macOS), never in settings, SQLite,
logs or the webview. The local provider is loopback-only and ignores proxy settings. Local profile
data (a name, and a 256 px PNG re-encoded from the user's picture so EXIF and GPS data are dropped)
and content-free lifetime totals stay in SQLite. The statistics image is drawn from those numbers,
includes the name or picture only when the user switches them on, and is saved only where the user
chooses.

## Threat boundaries and controls

| Threat or boundary | Implemented control | Remaining boundary |
| --- | --- | --- |
| Compromised renderer requests secrets or native shell | One typed application IPC entry point; narrow Tauri capability; CSP excludes remote frames/scripts/forms; no renderer token serialization, generic shell, filesystem or clipboard-read capability | A compromised renderer can invoke allowed user capabilities; this is not a defense against code executing as the same user |
| OAuth callback CSRF or code interception | Random state/nonce, constant-time comparisons, S256 PKCE, one-use loopback listener, exact callback path, method/request size/socket/deadline/connection limits; verified signed identity/issuer/audience/binding | Live official account eligibility and permission require real user sign-in; mocks cannot prove plan eligibility |
| Token theft from files or refresh races | Current-user DPAPI on Windows, a keyring- or Keychain-held key on Linux and macOS; fixed purpose entropy, secret zeroization, bounded credential records, OS profile/host locks, atomic writes, crash-interrupted refresh marker; rotating refresh tokens stay in native service | This protects at rest from other users/offline casual access, not from malware already executing as that same logged-in user |
| Logout or account switch during inference | Account-bound session cancellation; preference/catalog by actual account model slug; local removal and remote-revocation result are explicit | Remote revocation may be unavailable/offline; the UI reports whether it was confirmed |
| Prompt injection or over-editing | Source/context treated as untrusted quoted data, separate operation instructions, deterministic local rules, conservative validation of empty/expanded output and protected terms; URLs, emails, paths and code must be unchanged with none added, and every number keeps its value, sign and currency while its format may change ("3pm" → "3 p.m.") | A model can still alter meaning within permitted edits; user can inspect/copy original and use guarded undo |
| Hostile/corrupt model download | Pinned manifest revision, trusted HTTPS redirect hosts, expected size and SHA-256, bounded resume/content-range validation, disk reserve, locks, fsync and same-volume atomic installation | A valid hash establishes the catalog bytes, not the absence of native-engine parser defects |
| Untrusted local model or worker crash | Catalog-selected verified paths, bounded worker protocol, one inference at a time, cancellation/timeout kills worker, CPU fallback; explicit sibling executable paths, no shell interpolation | The worker runs as the user and is process isolation, not a restricted Windows sandbox; same-user replacement of installation/model files remains outside a privilege boundary |
| Clipboard/focus races (Windows) | Full advertised-format duplication or refusal, process lifetime/focused runtime identity (or, for a control re-created in place, the same window, process, control type, automation ID and position)/password/integrity checks, sequence and owner check under clipboard lock before restore, held-modifier refusal, complete SendInput count, delayed-render receipt | No atomic Win32 “paste only if focus is unchanged” call; receipt identifies a consumer, not its process; malicious clipboard managers can ignore privacy markers |
| Mac paste into the wrong field | Accessibility permission required; app process ID and start time, focused window, and the element's hash, role, identifier and position checked when dictation starts and again right before ⌘V; secure text fields and secure keyboard input refused; held modifiers waited for, then refused; pasteboard text put back only if it still holds the dictation | An app that exposes no focused element is checked by app and window only; no Mac call pastes only if focus is unchanged; the paste is confirmed only by a change in the field's length or caret; keyboard layouts that move V (Dvorak) are untested |
| Cancel during native preparation | Guarded paste/replacement variants test cancellation before publication, unique-span selection, and immediately before SendInput; restoration still runs after cancelled publication | There is a final machine-instruction race between a guard and global input injection; blocking foreign delayed clipboard owners have no per-call deadline |
| Elevated targets and secure desktop | Integrity/SID checked with query-only handles; higher-integrity targets are refused before mutation; no always-admin or uiAccess build | Elevated insertion is unsupported in the ordinary distribution; custom providers may misdeclare password status |
| Hook starvation or arbitrary typing collection | Separate helper/message loop, allocation-free callback, bounded queues, injected-event filter, 500 ms heartbeat, parent recovery, idle rearm, explicit active-state Cancel arming | Windows can silently remove a timed-out hook; process separation does not eliminate scheduler starvation or all RDP/session edge cases |
| DLL search hijacking | Application calls SetDefaultDllDirectories before native subsystem initialization; workers are resolved as explicit bundled paths | Unsigned, user-writable installation contents cannot provide authenticity against same-user tampering |
| Dependency/updater compromise | Locked dependencies, exact license exceptions, current advisory checks, pinned action commit IDs, generic CPU build configuration; updater artifacts require configured signature keys | No real Authenticode certificate or update signing secret is committed or supplied; release operators must provision/verify these and protect CI secrets |

## Trust-sensitive configuration

The OAuth production issuer/resource/endpoints are native constants checked against discovery. Test endpoint overrides remain in test code. Credentials never belong in `.env`, plaintext SQLite, WebView storage, localStorage, logs or support bundles. Do not enable HTTP debug logging or serialize `PendingSignIn`, its browser URL, raw `SecretTokens`, access-token headers or remote response bodies into diagnostics. Browser opening uses the native authorization transaction; no private application protocol is reverse engineered.

Custom transformation instructions are explicit user instructions; dictated/selected/context text must not be promoted into an instruction role by a frontend. Per-application profile rules are local settings, not hard-coded credentials or network destinations. Model IDs, dictionary imports and persisted identifiers are validated before forming paths/operations. Uninstalling a model removes only its managed revision files. Model migration copies/verifies before switching settings.

Updater signing and Windows Authenticode serve different purposes: updater signatures verify an update payload against the configured application public key; Authenticode identifies the publisher of Windows executables/installers. A SHA-256 sidecar checksum alone is not authenticity. Release packages are unsigned today on every platform ([release.md](release.md)); signing needs an operator-managed signer, timestamping and signature verification of the application, helpers and installer. Without a configured HTTPS update endpoint and public key, Onda never downloads or installs an update.

## Tests and open checks

Native guarded behavior, format preservation, password rejection, Unicode insertion, selection/undo and clipboard-copy races have focused tests. OAuth/storage/SSE behavior has deterministic local-server tests and DPAPI tests; the Linux keyring and macOS Keychain round trips are ignored tests that need a desktop session. ASR golden tests assert actual recognized speech, actual CPU fallback and worker cancellation; a successful process exit is insufficient. The dependency policy job runs `cargo deny` and `npm audit` on every pull request ([third-party-licenses.md](third-party-licenses.md)). What has been proven, and where, is in [VERIFICATION.md](../VERIFICATION.md).

Hosted CI cannot check a real ChatGPT sign-in, clean installs and upgrades, typing into real apps, Remote Desktop, suspend and CPU stress, or GPU drivers; those are in the manual matrix ([testing.md](testing.md)). No package is signed yet. Future changes that widen what history records, introduce telemetry, new model formats, uiAccess, a new cloud provider or broader accessibility observation must update this threat/data-flow model and expose explicit user controls.
