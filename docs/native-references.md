# Native research and provenance

Research date: 3 October 2026. Implementations in `eagle-platform` and `eagle-input` were written for this project. No competitor source was copied or materially adapted. Concepts were checked against the primary Windows APIs below; reading a project is not permission to reuse its code.

## Microsoft primary references

- [LowLevelKeyboardProc](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc): message-loop ownership, injected flags, silent removal, dedicated-thread advice, and the 1000 ms cap on Windows 10 1709+. This motivates callback isolation, bounded transport, and periodic reinstallation rather than treating heartbeat as proof of hook presence.
- [SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput): serial input batches, exact event-count check, held-modifier interference, and equal/lower-integrity restrictions. Windows does not report UIPI as an identifiable SendInput error, so process integrity is checked first.
- [Clipboard formats](https://learn.microsoft.com/en-us/windows/win32/dataxchg/clipboard-formats): ordered multiple formats, synthesized formats, private/GDI ownership, and Windows history/cloud exclusion markers. This motivates all-format preservation or refusal.
- [GetClipboardSequenceNumber](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getclipboardsequencenumber): sequence changes, delayed rendering, and zero when clipboard access is unavailable. Restoration checks sequence while holding the clipboard lock.
- [OleDuplicateData](https://learn.microsoft.com/en-us/windows/win32/api/ole2/nf-ole2-oleduplicatedata): global memory duplication plus special bitmap/palette handling. Enhanced metafiles use `CopyEnhMetaFileW`; old metafile pictures are refused to avoid an incomplete ownership implementation.
- [Using the clipboard](https://learn.microsoft.com/en-us/windows/win32/dataxchg/using-the-clipboard): hidden-window ownership and delayed rendering through `WM_RENDERFORMAT`. A read receipt improves diagnostics without pretending to identify the reader.
- [UI Automation connection timeout](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationclient/nf-uiautomationclient-iuiautomation2-put_connectiontimeout) and [transaction timeout](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationclient/nf-uiautomationclient-iuiautomation2-put_transactiontimeout): provider waits are reduced to 750 ms per call.
- [IUIAutomationTextRange::GetText](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationclient/nf-uiautomationclient-iuiautomationtextrange-gettext): bounded return length makes this preferable to unbounded ValuePattern reads for context.
- [WASAPI](https://learn.microsoft.com/en-us/windows/win32/coreaudio/wasapi): endpoint/session capture, invalidated-device errors, and Windows' shared audio engine. Eagle uses CPAL's WASAPI implementation instead of maintaining a second bespoke audio engine.

## Actual open-source implementation inspection

- [WhimprFlow Windows integration](https://github.com/Blueturboguy07/WhimprFlow/blob/04d477a75278fd4f8e6e25f55a34d7733d9d393b/src-tauri/src/win.rs) and [architecture/research](https://github.com/Blueturboguy07/WhimprFlow/blob/04d477a75278fd4f8e6e25f55a34d7733d9d393b/docs/ARCHITECTURE-DUAL-PLATFORM.md) were inspected at commit `04d477a75278fd4f8e6e25f55a34d7733d9d393b`. The Windows source's `paste_text` saves only plain text, sends input without checking the accepted count, and restores plain text without a sequence guard. Its research correctly identifies silent-hook-removal and process-isolation risks; several broader promises in the research exceed that Windows paste implementation. Eagle independently implements process supervision, integrity/control validation, format-preserving clipboard transactions, and explicit uncertain-outcome diagnostics.
- [Handy current Windows paste transaction](https://github.com/cjpais/Handy/blob/5ec58f696354fcf64ae831102e673779e0249717/src-tauri/src/paste_tx/windows.rs), [legacy clipboard path](https://github.com/cjpais/Handy/blob/5ec58f696354fcf64ae831102e673779e0249717/src-tauri/src/clipboard.rs), and [recorder](https://github.com/cjpais/Handy/blob/5ec58f696354fcf64ae831102e673779e0249717/src-tauri/src/audio_toolkit/audio/recorder.rs) were inspected at commit `5ec58f696354fcf64ae831102e673779e0249717`. Current `paste_tx/windows.rs` uses a hidden window and delayed rendering; it is materially stronger than the legacy text-or-image restoration path. The transaction source skips some unsupported/oversized formats. Eagle follows the Windows delayed-render concept independently and refuses a transaction when any advertised format cannot be preserved. Handy's real-time ring transport reinforces the value of keeping capture callbacks away from allocation/logging/locks. None of these source bodies were copied.
- [CPAL 0.18.2 source/API](https://docs.rs/cpal/0.18.2/cpal/traits/trait.DeviceTrait.html) was inspected locally from the crates.io package, including `host/wasapi/device.rs` and `traits.rs`. Stable `DeviceId` is backed by `IMMDevice::GetId`, unlike CPAL 0.16's public name-only device interface. The manifest uses 0.18.2 for this concrete reason. License: Apache-2.0.
- [rubato 0.16.2](https://docs.rs/rubato/0.16.2/rubato/struct.FftFixedInOut.html) and [rtrb](https://docs.rs/rtrb/) APIs were checked from their downloaded packages. Rubato's bounded fixed-input FFT implementation is sufficient for deterministic sample-rate conversion; its API is intentionally pinned to this minor series rather than importing an unrelated major migration. Licenses: MIT; MIT/Apache-2.0 respectively.
- [Microsoft windows-rs](https://github.com/microsoft/windows-rs): generated COM bindings provide UIA, and `windows-sys` supplies narrow Win32 calls. Both packages use MIT/Apache-2.0. This implementation uses the reviewed 0.58/0.59 API series directly; CPAL internally brings its own newer compatible Windows bindings.

The application's `docs/third-party-licenses.md` records distribution attribution. Competitor names are research references, not product branding. Hook callbacks and telemetry never collect arbitrary keystrokes, selected text, or clipboard content into logs.
