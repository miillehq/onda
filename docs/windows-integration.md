# Windows integration

The native implementation is in `crates/eagle-platform`; the keyboard helper and parent supervisor are in `crates/eagle-input`. These crates target Windows and keep microphone samples, focused-field text, and clipboard data out of the renderer. Native calls belong on application worker threads, never the WebView event loop.

## Microphone capture

`AudioCapture::enumerate_devices()` returns public device IDs, names and default status. CPAL 0.18.2 uses Windows WASAPI and exposes the actual `IMMDevice` endpoint ID, avoiding ambiguity between microphones with the same display name. A `None` device ID resolves the current Windows default at the start of each recording. An explicit unavailable endpoint returns an error rather than switching to an unintended microphone.

`AudioCapture::start(CaptureOptions)` starts a dedicated owner thread and acknowledges stream startup. `stop()` closes the stream, drains transport, and returns mono 16 kHz float samples with diagnostics. `cancel()` discards samples and closes capture. Dropping the capture owner cancels it. Sample-format conversion supports signed/unsigned 8-, 16-, 24-, 32-, 64-bit PCM and float32/64. DSD is rejected. Multiple channels are averaged before resampling; this suits ordinary voice inputs, but oppositely phased channel pairs can cancel.

`poll_completion(&mut self)` is nonblocking and returns `CaptureCompletion::Running` or `Finished`; microphone/disconnected-worker failures are reported immediately. The session caches the complete result, so repeated polling does not consume audio/error ownership and `stop()` can still retrieve it. The application's generation-tagged recording monitor polls every 250 ms during Recording, finalizes a finished capture, and cancels/fails only its matching generation on fatal capture error. A completed or failed session is still owned until Stop/Cancel; `is_recording()` indicates that ownership, so it must not substitute for completion polling.

The real-time audio callback does no allocation, logging, I/O, mutex acquisition, or resampling. A fixed two-second `rtrb` ring transfers mono frames to the owner thread. Ring overflow and asynchronous stream errors are explicit failures, preventing incomplete audio from being presented as complete. Capture is bounded to 1–600 seconds, defaults to 180, and rejects source rates above 192 kHz. A duration/frame cap finalizes successfully with `diagnostics.limitReached = true` rather than discarding the dictated prefix as an error; the final callback is capped at the configured frame count. Incremental band-limited FFT resampling trims filter delay and preserves the exact source duration. Only 16 kHz output is retained: approximately 11.52 MB for 180 seconds or 38.4 MB for 600 seconds, plus the bounded ring/FFT buffers. Allocation failure is reported.

Diagnostics report source rate/channels, duration, mono peak, RMS, clipped mono-frame count, and a silence flag. The silence threshold does not truncate push-to-talk recordings. Microphone tests use this same capture path. Raw audio is never written to disk here. Hot-plug invalidation fails the current operation; the next recording re-enumerates/resolves devices. There is no continuous device watcher or silent mid-recording reroute recovery. CPAL can report a Windows default-device change; Eagle treats any stream error as a disconnected/incomplete recording and closes it.

## Foreground target and scoped accessibility

`WindowsTargetService::snapshot()` records the foreground HWND, PID, process creation timestamp, executable name, focused UI Automation runtime ID, password status and process integrity level. Process lifetime prevents a recycled PID from matching. Empty/unknown runtime identities fail closed. It also records the focused control's structure (owning process, control type, automation ID, framework and bounding rectangle, never text). Chromium-based apps such as Electron apps, WebView2 and browsers can rebuild their accessibility tree while transcription or polish runs, giving the same field a new runtime ID. A changed runtime ID is accepted only in the same window and process when that structure still matches within 4 px (height may grow); any other change is a focus change. Each acceptance is logged as "focused control was re-created in place". A password control is rejected before its text is queried. A higher-integrity target is rejected before clipboard mutation or input injection. Eagle does not require administrator privileges or try to bypass UIPI.

The focused element normally belongs to the foreground process. Hosted content (WebView2, CEF and similar, as in Onda's own window, the new Teams or the new Outlook) is rendered by a helper process instead; such an element is accepted only when its process owns the window holding keyboard focus (`GetGUIThreadInfo`) inside the same foreground top-level window, and that process runs at no higher integrity. The recorded identity stays the top-level app, so app profiles and revalidation are unchanged.

The UIA client joins the MTA COM apartment and uses `IUIAutomation2` connection/transaction timeouts of 750 ms per provider call. Callers must use a worker thread. A pooled worker that a library already placed in a single-threaded apartment is used as it is (cross-process UIA works from either) and is never uninitialized by Eagle; audio device enumeration runs on its own short-lived thread so the audio backend's STA does not leak into shared workers. These are provider-call bounds rather than a single operation deadline. UI Automation is an external provider interface and may still encounter OS/provider failures. No accessibility events are subscribed globally and no background windows are traversed.

`selected_text(target, limit)` requires exactly one nonempty `TextPattern` selection. `context(target, limit)` and `field_text(target, limit)` read only the focused control's `DocumentRange`. Reads are bounded using `GetText(limit + 1)` and refuse oversized data; the bound is conservative in UTF-16 code units, so emoji can reach the limit sooner. `ValuePattern::CurrentValue` is intentionally avoided because that API returns the whole unbounded value before it can be truncated. Providers without `TextPattern` return `SelectionUnavailable`. Context is collected only after an explicit operation and its enabled settings permit it.

For optional correction learning, the application may call `field_text` at most three times inside its opt-in twelve-second window after insertion. Each call revalidates the original focused target. This is narrow, bounded sampling, not a `ValueChanged` event implementation or keylogger. Scope and opt-in scheduling are enforced by the application layer. Providers that do not expose bounded field text cannot participate.

`replace_selection` verifies the selected source still matches before clipboard replacement. `replace_unique_text(target, expected_document, needle, replacement, shortcut)` supports safe transform undo: it requires an unchanged complete focused document and exactly one occurrence, locates/selects the range through UIA, then revalidates its selected text before pasting. Duplicate occurrences, document edits, target changes, password fields, or unsupported providers refuse undo. It never sends a general Ctrl+Z that could undo unrelated application work.

## Clipboard transaction and input

`paste(target, text, PasteShortcut)` serializes clipboard operations and refuses held physical modifiers. Supported chords are Ctrl+V, Ctrl+Shift+V, and Shift+Insert. The application should select a chord through per-application preferences, particularly for terminals. A dedicated, nonactivating message-only window owns a delayed-render Unicode format. Privacy markers exclude temporary dictated text from Windows clipboard history/cloud synchronization; third-party clipboard managers can ignore these advisory markers.

Before changing the clipboard, Eagle enumerates and duplicates **every** currently advertised format. It preserves HGLOBAL-backed formats (Unicode/ANSI text, RTF, HTML, DIB, files, registered application formats), bitmaps, palettes, and enhanced metafiles. Old metafile pictures, display/owner-managed formats, private handles, zero-sized formats, more than 128 formats, or more than 64 MiB total cause a refusal before mutation. A supported format whose delayed-render owner returns no data, or that cannot be duplicated, is skipped, because refusing the whole dictation over one format the owner can no longer render helped no one. Opening the clipboard retries for about 600 ms while another app holds it. This conservative policy means an unusual clipboard item can temporarily prevent dictation insertion; the application retains the transcript for explicit copying/retry.

All temporary allocations are prepared first. The clipboard is acquired with ten bounded 10 ms retries. Foreground/process/control identity and integrity are checked again before publishing and immediately before `SendInput`. All chord events are submitted together. Partial input acceptance triggers key releases and returns an injection failure. The temporary text renders only when a consumer requests it via `WM_RENDERFORMAT`. The worker pumps its owner window for up to one second and waits 200 ms after a read before restoring.

Restoration compares the clipboard sequence **after acquiring the clipboard lock**, and also checks owner identity. A user/new application copy wins; Eagle will not overwrite it. The previous format handles are already duplicated before publication, reducing restore-time allocation risk. Windows does not offer an atomic multi-format commit: if publication/restoration fails after clearing, the operation returns a structured clipboard error, and preservation cannot be guaranteed against an OS allocation/API failure. Clipboard `GetClipboardData` can ask a prior delayed-render owner to respond; unlike UIA this Win32 transfer has no per-call deadline. A broken clipboard owner is an external integration limitation.

`InsertionOutcome` reports `inputInjected`, `clipboardReadObserved`, `clipboardRestored`, and `clipboardChangedByOther`. A render receipt proves that a clipboard consumer read the text, not that the foreground application edited its document; clipboard readers cannot be authenticated through this API. Input acceptance alone is not an insertion proof. The application must expose uncertain results instead of claiming confirmed text insertion when no read was observed. UIA checks narrow the race before input, but Win32 provides no atomic “send input only if focus remains this control” operation. A last-instant physical focus change remains a platform limitation.

The application uses `paste_guarded`, `replace_selection_guarded`, and `replace_unique_text_guarded`, which accept a final `should_cancel: impl Fn() -> bool` callback. The callback is checked before native work, before publication/selection, and immediately before SendInput. Cancellation after publication still runs sequence-guarded restoration and returns `PlatformError::Cancelled`. Unguarded methods remain conveniences for explicit synchronous callers/tests; they must not be used by cancellable dictation workflows.

`copy_text_to_clipboard(text)` / `WindowsTargetService::copy_to_clipboard` are deliberate user Copy actions. They replace the clipboard without restoration or foreground requirements and retain the privacy markers. There is no frontend command to read arbitrary clipboard content.

## Keyboard helper

`eagle-input.exe` owns `WH_KEYBOARD_LL` on its message-loop thread, independently of ASR and WebView work. The process requests above-normal scheduling priority. The callback tracks a fixed 256-key state array, ignores `LLKHF_INJECTED`, evaluates at most 32 configured chords, suppresses matched trigger key down/up, and emits only a binding index to a bounded queue. Modifier keys pass through. It does not send key codes for arbitrary typing, log keystrokes, allocate strings, block on stdout, or run business logic in the callback.

Named actions are `dictation`, `transform`, `command`, `toggle`, and `cancel`. Custom transforms attach an optional `transformId`. IDs are unique per transform action, at most 128 bytes, and invalid for other actions. Chords and non-transform actions cannot be duplicated. Each binding requires one nonmodifier virtual key and exact modifier matching. Modifier-only shortcuts are intentionally unsupported; standard Windows shortcuts may conflict and should be configurable.

The helper reads a single JSON configuration line from stdin (protocol v1, maximum 16 KiB) and emits bounded JSONL on stdout. For example:

```json
{"protocolVersion":1,"bindings":[{"action":"dictation","transformId":null,"virtualKey":32,"modifiers":{"control":true,"shift":false,"alt":false,"windows":true}}]}
```

Events are `ready`, `heartbeat`, `pressed`, `released`, `reset`, or `error`. Pressed/released include `action` and `transformId`; heartbeat includes `uptimeMs`. Serialization and pipe writes occur on a separate thread. Queue overflow causes helper termination/recovery rather than blocking the hook. Closing stdin or sending `{"command":"shutdown"}` exits the process. The parent retains stdin while the helper runs. Control lines are capped at 256 bytes.

`HelperSupervisor::set_operation_active(bool)` sends `{"command":"setOperationActive","active":true}` only when state changes. The reader posts a lightweight message to the hook thread. Idle Cancel chords pass through without events; active Cancel consumes its trigger down/repeat/up, and bare Escape remains usable while the PTT modifiers/trigger are held. Cancel uses a separate latch so it does not depend on releasing the PTT trigger first. The parent synchronizes its active operation state on each polling iteration. Reset disarms cancellation; ordinary periodic idle rearm preserves the parent's armed state.

The message loop emits a heartbeat every 500 ms. `HelperSupervisor::start(explicit_sibling_path, config)` canonicalizes the helper path and launches it hidden without shell/PATH resolution. `poll(Duration)` monitors exit and a three-second heartbeat gap, kills/restarts unhealthy helpers, and emits `Reset`. Restarts are limited to three per minute; exhaustion reports shortcuts unavailable. The application must cancel any recording on Reset/Error. Dropping the supervisor kills/waits for its child. Protocol messages and configuration are version checked.

Windows can silently remove a hook after exceeding its timeout; heartbeat alone cannot establish hook presence. The helper reinstalls its hook every 30 seconds while no trigger is active, limiting undetectable removal. It reconciles held trigger state every heartbeat using `GetAsyncKeyState` and emits Reset on a missed release/desktop loss. Recovery on resume/session changes is through these mechanisms, not dedicated WTS or power notifications. RDP and unusual desktop transitions require the manual matrix below. Process isolation reduces starvation risk but is not a Windows scheduler guarantee.

## Validation and support limits

On the implementation host, ordinary native tests passed, and the opt-in desktop harness passed real Win32 Edit Unicode/emoji/Japanese paste, delayed-render receipt, custom-format restoration, focused-field reading, selection replacement, unchanged-document undo, stale-document refusal, cancellation after publication, external clipboard-copy races, and password refusal. The helper process probe passed startup, two 500 ms heartbeats, and clean shutdown. Test commands:

```powershell
cargo test -p eagle-platform -p eagle-input
$env:EAGLE_DESKTOP_TESTS = '1'
cargo test -p eagle-platform real_edit_unicode -- --ignored --test-threads=1
```

The interactive harness opens its own controlled windows and temporarily changes the clipboard after preserving the original. Run it while the desktop is idle. CI leaves it ignored. It cannot substitute for the release application matrix: Notepad, Edge/Chrome text fields and password fields, VS Code/Electron, WPF/WinUI, Windows Terminal/PowerShell, RDP, 32-bit targets, elevated targets, foreground changes during inference, clipboard managers, user copies during paste, microphone unplug/default switch, suspend/resume, and hook stress under CPU load.

Native APIs used require Windows 8 or earlier individually; the full application's documented Tauri/WebView2 release floor governs actual support. Windows 11 x64 is the production target. ARM64-compatible Win32 types are used, but these crates have only been compiled/exercised on x64 here. A signed `uiAccess` build would require separate security/release work and is not enabled. Password protection relies on the target provider honestly declaring its secure status; custom canvas editors and defective accessibility providers cannot be treated as verified secure/editable fields.
